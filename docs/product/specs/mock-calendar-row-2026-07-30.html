2 · The left sub-line, once the clock moves right

In A and B the sub-line still says “1h · until 11:00 AM”. That is two times in one row — start on the right, end on the left. Two ways to settle it:

A1 · Keep the end time (recommended)

Reads as a sentence: “New Event 1, one hour, until 11 — starting 10:00 AM.” Nothing is lost, and the end time is the thing you actually plan around.

A2 · Duration only

Quietest possible row. Cost: you lose “when does this free up”, which is the one number the day-capacity story is built on.

3 · The refresh glyph

I verified the plumbing first: pull-to-refresh on Today calls the same cap.refresh() the glyph calls — it does a real device-calendar re-read (useDayCapacity.ts). On top of that the calendar re-reads on screen focus and on app foreground. So the glyph is a fourth way to do something that already happens three ways automatically.

My call

A + A1 + R1. A makes the calendar row a structural twin of the task row, so the whole Today list reads on one grid — title left, number right, no dividers. A1 keeps the end time, which is the number the capacity story runs on. R1 because refresh already happens on focus, on foreground, and on pull — a permanent glyph for it is chrome with no job. If you'd rather not lose the explicit tap, take R3: it costs nothing while fresh and is honest when it isn't.
